# Synthetic Envoy WASI probe

This standalone, dependency-free Proxy-Wasm ABI 0.2.1 fixture checks host availability in the digest-pinned Envoy image from `deploy/gateway/config.py`. Run `python3.13 scripts/test-envoy-wasi-probe.py` with the Rust `wasm32-unknown-unknown` target, Docker image already present, and OpenSSL. It builds offline into ignored `target/`, generates temporary synthetic TLS certificates, and removes its container and temporary files. It does not mount the CA private key or upstream keys.

The fixture checks its Rust formatting and builds with the committed lockfile. Run `python3.13 tests/fixtures/envoy-wasi-probe/test_cleanup.py` for the controlled cleanup-failure regression. The existing managed-gateway CI job requires both checks and the actual probe before its native dependents can pass. Successful cleanup is required before the harness prints PASS. The reconstructed worker fixture passed on macOS on 2026-10-29; integrated and hosted checks must pass on the final candidate before merge.

The request callback calls WASI realtime and monotonic clocks, requires a nonzero realtime value and monotonic advancement in a bounded loop, and requires two successful 32-byte random calls to differ. Only on success does it return the constant `wasi-probe-ok` marker. It does not read request bodies or output clock values or random bytes. A fallback 503 makes failure visible. Availability and variation do not establish entropy quality, unpredictability, or suitability for authentication. This fixture establishes no capture or authority behavior, and does not assess production security or performance.
