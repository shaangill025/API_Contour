# Managed gateway: local transport fixture

The owner approved Envoy for local MVP implementation and synthetic tests on 2026-10-29. The fixture uses the Envoy community image `envoyproxy/envoy:v1.37.11` at OCI index digest `sha256:7765ad61185fca9c9a770c9e2cad640d085d708ae9c22f3741345e88331472a4`. On 2026-10-29 `docker buildx imagetools inspect` returned linux/amd64 and linux/arm64 manifests for that index. Envoy is [Apache-2.0 licensed](https://github.com/envoyproxy/envoy/blob/v1.37.11/LICENSE). The [release notes](https://github.com/envoyproxy/envoy/releases/tag/v1.37.11) describe an eMudhra trust-bundle fix specifically for the distroless image. Review [security advisories](https://github.com/envoyproxy/envoy/security/advisories), lifecycle and image pin again before further use; this review is not a vulnerability clearance.

Pull the exact pinned image explicitly first, then run `python3 scripts/test-managed-gateway.py` with Docker, OpenSSL and Python 3. The test checks the pinned image is present and prevents implicit pulls. The script creates a private temporary directory and synthetic CA, server certificates and keys with explicit X.509 extensions; it verifies the chains under OpenSSL strict mode and enables strict downstream verification on every platform; it deletes those artifacts and the uniquely named container on exit. On macOS it uses Docker Desktop's fixed `host.docker.internal` endpoint and an ephemeral loopback published port. On Linux it uses Docker host networking with both upstream and Envoy listener bound to `127.0.0.1`, and an ephemeral unprivileged listener port; it does not use Docker port publishing. Other platforms fail explicitly. Both profiles avoid MVP stack ports and volumes. Linux host networking requires a local Linux Docker daemon that shares the runner's network namespace; remote daemons or Docker Desktop's VM do not provide that profile. The selected Linux port is released before Envoy binds, so a competing process may claim it and cause a test failure. The generated Envoy configuration selects one fixed operator-specified endpoint, SNI and exact DNS SAN, with an explicit CA. The downstream listener uses synthetic TLS and a fixed route. The fixture container runs as the invoking nonroot UID with read-only root and individual read-only config, downstream certificate/key and upstream CA mounts, dropped capabilities, no privilege escalation, bounded CPU, memory and PIDs, no admin endpoint, access log or Docker log driver, and finite connection/request/idle limits. The generated configuration is local test material, not a production deployment template.

Executed on 2026-10-29 on macOS with Python 3.13.11 and OpenSSL 3.6.3, with strict verification enabled: valid two-leg HTTPS with explicit upstream TLS 1.2 and TLS 1.3 profiles each returned 201 with the synthetic request path, header and body and response status, header and body intact. With the upstream fixture restricted to TLS 1.2, wrong upstream DNS SAN, untrusted upstream CA and expired upstream certificate each returned 503 after the upstream observed a certificate-related TLS alert, with zero HTTP handler calls. TLS 1.3 certificate-negative cases were not verified. The generated upstream configuration explicitly allows TLS 1.2 and TLS 1.3. A client using an untrusted downstream CA failed TLS verification; plaintext on the TLS listener was rejected. The test checked that Docker logging was disabled and inspected the available log command output for the synthetic sentinel. These assertions do not establish absence of data in every possible sink.

This is transport evidence only. It does not implement or verify capture, sanitization, instance attribution, causal inference, client mTLS identity, certificate rotation, rollback, HA, streaming/cancellation semantics, exhaustive HTTP framing, performance or production security. Static secrets and the Docker Desktop hostname are fixture choices; customer traffic, keys and production routes are outside this approval. The upstream server binds host loopback. The Docker Desktop macOS profile was exercised locally; the Linux host-network profile has not been executed here and requires the hosted Linux CI run before merge.
