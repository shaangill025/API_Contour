# Envoy in-process capture feasibility

Status: gateway body capture remains a proposal, 2026-10-29. The transport fixture and separate [Envoy host-service probe](envoy-wasi-probe.md) are implemented. Shared authority-reply validation returns checked data only; the Wasm transport and private live-authority owner still need implementation. No production capture, universal coverage or performance acceptance is claimed.

## Existing boundaries and evidence

* `crates/contour-wasm/src/lib.rs` exposes a custom integer-only structural canonicalization ABI, not Proxy-Wasm callbacks. `crates/contour-wasm/README.md` explicitly says its input is already structure-only, no clock or authority, and does not authorize or sanitize raw traffic. Loading this module as-is as an Envoy filter cannot implement capture.
* `crates/contour-core/src/extract.rs` extracts a shape without values and uses policy-controlled names and a 65,536-byte bound. `extract_json` calls `std::time::Instant::now()`, and its trusted `InspectionClock` entry points preserve the 2 ms checkpoints and reject missing or backward readings. On `wasm32-unknown-unknown`, native `Instant` is unavailable at runtime; an injected real elapsed source is required, not a constant clock or relaxed deadline. The existing JSON extractor consumes a complete bounded document, not incremental fragments. A field-name policy passed by a caller is not itself an authorization grant.
* `crates/contour-core/src/policy.rs` verifies Ed25519 over the original signed bytes, identity and lease, but explicitly does not establish enrollment, revocation or anti-rollback. `admission.rs` checks source/metadata/policy for records; `docs/collector-construction.md` says checked structure alone is not admission. Signed snapshot mapping and native pre/post inspection guards are implemented. The Wasm adapter still needs authenticated transport, private live ownership and real pre-body-access tests.
* `crates/contour-delivery/src/authority.rs` and `OWNER.md` show the existing online grant: fresh 32-byte challenge, mutually authenticated fixed TLS endpoint, response/challenge/identity/exact source checks, signed policy validation, checked-at and monotonic lease. `CollectorOwner` starts paused and has private live state, highwater/queue reconciliation and expiry checks. It depends on Tokio, Rustls, sockets and `Instant`; it is not directly usable unchanged in a Wasm VM. `SourceAssignment::new` alone is a caller-constructible data object, not authenticated source evidence.

## Pinned host evidence and limits

The approved image reports `0ce6eee982e6df4a873b28184b396eeacfad938f/1.37.11/Clean/RELEASE/BoringSSL`. Its [dependency manifest](https://github.com/envoyproxy/envoy/blob/0ce6eee982e6df4a873b28184b396eeacfad938f/bazel/repository_locations.bzl) pins Proxy-Wasm host `c8868da77499d414f3dcd07e4fbe584dc9a1c30d` and BoringSSL `0.20250514.0`. The host [WASI implementation](https://github.com/proxy-wasm/proxy-wasm-cpp-host/blob/c8868da77499d414f3dcd07e4fbe584dc9a1c30d/src/exports.cc) routes clock IDs 0 and 1 separately; the [Envoy context](https://github.com/envoyproxy/envoy/blob/0ce6eee982e6df4a873b28184b396eeacfad938f/source/extensions/common/wasm/context.cc) uses system and monotonic time. The [real time source](https://github.com/envoyproxy/envoy/blob/0ce6eee982e6df4a873b28184b396eeacfad938f/source/common/common/utility.h) uses `steady_clock` for monotonic time. The actual probe observed ID 1 advancing; no wall-clock-change experiment was performed. Binary self-report and source review are not authenticated build provenance or security clearance.

The host uses `RAND_bytes` for WASI randomness. The pinned [BoringSSL contract](https://github.com/google/boringssl/blob/0.20250514.0/include/openssl/rand.h) returns success or aborts when sufficient randomness cannot be obtained. The ignored return is therefore not, by itself, evidence of a vulnerability with that backend. Initialization can block and entropy failure can terminate Envoy rather than return a recoverable guest error. Build flags, OS entropy, VM cloning and availability behavior need deployment qualification; sample variation is not entropy-quality proof.

Host availability does not mean Rust's `wasm32-unknown-unknown` standard APIs expose these services. Use explicit inspected imports or a supported reactor. Require fresh unpredictable 32-byte challenges with no fixed fallback, real monotonic extraction/lease timing and trusted wall-clock policy validation. Recoverable import, clock or timing failure must pause capture; fatal host failures require proxy availability handling. Test the actual adapter's failure behavior.

## One proposed next slice

Build a separate, local-only Rust Proxy-Wasm filter around the existing core, initially for one fixed operator-configured gateway source, route and `application/json` request body. Keep the tested structural ABI intact. Use the existing dependencies where possible; a Proxy-Wasm SDK, if needed, is a new dependency requiring review before installation. Reuse `check_authority_reply` for bounded checked data. The Wasm owner must privately construct live authority only after authenticated transport binds the response to its generated challenge, identity, exact sources, signed policy, time and revision/content highwater. Checked data alone cannot create that authority. The host transport must dispatch to one explicitly configured Envoy cluster with verified CA, exact SAN and client identity; demonstrate that this is equivalent to the native endpoint's mTLS identity and bounded timeout/response semantics. An HTTP callback, an unsigned reply, a policy signature alone or caller-supplied source must never manufacture a grant. Start paused; refresh failure, cancellation, stale/revoked/disabled policy or lease expiry disables body reads. Handle per-worker VM ownership and restart/highwater explicitly; do not turn a cold cache into a grant.

On request headers, check the live grant and authorized fixed source/route/content type **before calling the body buffer hostcall**. Return Continue on every callback; never pause the application stream to obtain a policy or wait on a queue. For each authorized stream, copy only bounded body fragments into private per-stream Wasm memory; clear on completion, limit breach, authority loss, malformed input, cancellation and deletion. Extract only on a complete unencoded JSON body under the existing byte/time/depth/field limits; oversize, unsupported encoding, incomplete body, trailers or ambiguous callback/buffer behavior must drop capture or produce a deliberately bounded partial outcome, never treat a prefix as complete JSON. Validate actual Envoy callback offsets and fragmentation with chunked and content-length HTTP/1 traffic; do not assume body callback buffer lengths are cumulative. The raw bytes necessarily exist transiently in Envoy and Wasm memory; no raw body or sensitive metadata may go to any plugin queue, HTTP dispatch, logs or disk. Map signed policy names to `ExtractionPolicy` without widening permissions, then apply shared admission to a structural draft before any queue or export. Recheck authority immediately before extraction and admission; drop on loss. Use the existing trusted host-clock entry point without changing its 2 ms checkpoints.

Initially emit only an in-memory, bounded synthetic structural assertion in the integration fixture; no queue/export is necessary for the first proof. Tests must show the module loaded in the exact digest-pinned Envoy, real clock and RNG import behavior, authenticated online challenge and replay/wrong-source/expired/disabled/rollback failures before any body hostcall, and a successful signed grant. Drive fragmented request bodies, empty/oversize/malformed/encoded/cancelled bodies, multiple concurrent streams, authority expiry midstream and trap/restart. Check unchanged request/response forwarding and bounded memory/time, plus synthetic sentinel scans of accessible logs and artifacts. Exercise host-call failure, timeout and queue-full behavior, and prove traffic continues when capture is unavailable; Envoy filter fail-open configuration and startup/update failure behavior require separate real tests. Measure synchronous callback cost and the gateway's overhead rather than inferring nonblocking behavior from `Continue`. Existing JSON parsing allocates and runs synchronously, so a two-millisecond checkpoint is a limit mechanism, not proof of p99 latency or full preemption. Confirm whether retained Wasm memory clearing is observable and avoid claiming zeroization of all VM/host copies.

A passing synthetic slice would establish only that this fixed gateway and narrow JSON profile enforce the tested local privacy boundary. Production requires further review of host security posture, policy/secret lifecycle, enrollment and revocation, durable anti-rollback across restarts, capture source ownership, export authorization, resource isolation, request cancellation, deployment, rotation, HA and measured performance.
