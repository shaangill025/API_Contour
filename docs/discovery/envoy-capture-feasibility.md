# Envoy in-process capture feasibility

Status: design/inspection only, 2026-10-29. A small **synthetic** Proxy-Wasm HTTP/1 JSON prototype is plausible, but the repository does not yet have an authorized in-process gateway capture path. The local Envoy fixture proves transport only. No Wasm module was built or run in Envoy for this investigation, and no claim is made about production capture, arbitrary decryption, all HTTP traffic, or performance.

## Existing boundaries and evidence

* `crates/contour-wasm/src/lib.rs` exposes a custom integer-only structural canonicalization ABI, not Proxy-Wasm callbacks. `crates/contour-wasm/README.md` explicitly says its input is already structure-only, no clock or authority, and does not authorize or sanitize raw traffic. Loading this module as-is as an Envoy filter cannot implement capture.
* `crates/contour-core/src/extract.rs` extracts a shape without values and uses policy-controlled names and a 65,536-byte bound. `extract_json` calls `std::time::Instant::now()`, and its private `run` accepts an elapsed-time function with 2 ms checkpoints. On `wasm32-unknown-unknown`, native `Instant` is unavailable at runtime; an injected real elapsed source is required, not a constant clock or relaxed deadline. The existing JSON extractor consumes a complete bounded document, not incremental fragments. A field-name policy passed by a caller is not itself an authorization grant.
* `crates/contour-core/src/policy.rs` verifies Ed25519 over the original signed bytes, identity and lease, but explicitly does not establish enrollment, revocation or anti-rollback. `admission.rs` checks source/metadata/policy for records; `docs/collector-construction.md` says checked structure alone is not admission. Policy-to-extractor mapping, permission before raw body access, and authority ownership therefore need explicit implementation and tests.
* `crates/contour-delivery/src/authority.rs` and `OWNER.md` show the existing online grant: fresh 32-byte challenge, mutually authenticated fixed TLS endpoint, response/challenge/identity/exact source checks, signed policy validation, checked-at and monotonic lease. `CollectorOwner` starts paused and has private live state, highwater/queue reconciliation and expiry checks. It depends on Tokio, Rustls, sockets and `Instant`; it is not directly usable unchanged in a Wasm VM. `SourceAssignment::new` alone is a caller-constructible data object, not authenticated source evidence.

## Host evidence and unresolved pin check

[Proxy-Wasm ABI v0.2.1](https://github.com/proxy-wasm/spec/blob/main/abi-versions/v0.2.1/README.md) specifies per-stream request/response body callbacks, buffer reads, and asynchronous HTTP dispatch. Envoy's [1.37.8 Wasm API documentation](https://www.envoyproxy.io/docs/envoy/v1.37.8/api-v3/extensions/wasm/v3/wasm.proto) lists WASI `clock_time_get` and `random_get` as implemented and allow-listable, identifies V8 among runtimes, and states capability-input sanitization is unimplemented. This is evidence for the 1.37 family, **not verification of the pinned 1.37.11 image**: the exact [v1.37.11 proto source](https://github.com/envoyproxy/envoy/blob/v1.37.11/api/envoy/extensions/wasm/v3/wasm.proto) and [host implementation](https://github.com/envoyproxy/envoy/blob/v1.37.11/source/extensions/common/wasm/context.cc) were unavailable through the research tool. Verify those exact sources and run import/capability probes against the pinned image before relying on them. Envoy's 1.37.8 documentation also warns of an unknown security posture for its Wasm service; assess the exact HTTP filter and pinned runtime separately rather than treating this as a security approval.

WASI p1 `clock_time_get`/`random_get` are possible host services, not proof that Rust's `wasm32-unknown-unknown` std exposes them or that a chosen module imports them. Choose a supported `wasm32-wasip1` reactor or explicitly import the host functions and inspect its imports; test monotonic and realtime clock IDs, failures/backward readings and entropy errors in the actual image. Require fresh unpredictable 32-byte challenges; never replace a failed RNG with a fixed value. Use real monotonic elapsed time for extraction and lease, authenticated checked-at plus signed expiry, and local wall-clock policy validation. Trap, denied import, clock failure or invalid timing must pause capture and never create authority.

## One proposed next slice

Build a separate, local-only Rust Proxy-Wasm filter around the existing core, initially for one fixed operator-configured gateway source, route and `application/json` request body. Keep the tested structural ABI intact. Use the existing dependencies where possible; a Proxy-Wasm SDK, if needed, is a new dependency requiring review before installation. First extract a narrowly scoped pure authority-reply verifier/state transition from native delivery, shared by both hosts, with private construction of a live grant only after the authenticated response is bound to the generated challenge, tenant/collector, exact source set, signed policy, times and revision/content highwater. The host transport must dispatch to one explicitly configured Envoy cluster with verified CA, exact SAN and client identity; demonstrate that this is equivalent to the native endpoint's mTLS identity and bounded timeout/response semantics. An HTTP callback, an unsigned reply, a policy signature alone or caller-supplied source must never manufacture a grant. Start paused; refresh failure, cancellation, stale/revoked/disabled policy or lease expiry disables body reads. Handle per-worker VM ownership and restart/highwater explicitly; do not turn a cold cache into a grant.

On request headers, check the live grant and authorized fixed source/route/content type **before calling the body buffer hostcall**. Return Continue on every callback; never pause the application stream to obtain a policy or wait on a queue. For each authorized stream, copy only bounded body fragments into private per-stream Wasm memory; clear on completion, limit breach, authority loss, malformed input, cancellation and deletion. Extract only on a complete unencoded JSON body under the existing byte/time/depth/field limits; oversize, unsupported encoding, incomplete body, trailers or ambiguous callback/buffer behavior must drop capture or produce a deliberately bounded partial outcome, never treat a prefix as complete JSON. Validate actual Envoy callback offsets and fragmentation with chunked and content-length HTTP/1 traffic; do not assume body callback buffer lengths are cumulative. The raw bytes necessarily exist transiently in Envoy and Wasm memory; no raw body or sensitive metadata may go to any plugin queue, HTTP dispatch, logs or disk. Map signed policy names to `ExtractionPolicy` without widening permissions, then apply shared admission to a structural draft before any queue or export. Recheck authority immediately before extraction and admission; drop on loss. The current extractor's private elapsed callback needs a narrowly exposed host-clock entry point that preserves native behavior and the same 2 ms checkpoints.

Initially emit only an in-memory, bounded synthetic structural assertion in the integration fixture; no queue/export is necessary for the first proof. Tests must show the module loaded in the exact digest-pinned Envoy, real clock and RNG import behavior, authenticated online challenge and replay/wrong-source/expired/disabled/rollback failures before any body hostcall, and a successful signed grant. Drive fragmented request bodies, empty/oversize/malformed/encoded/cancelled bodies, multiple concurrent streams, authority expiry midstream and trap/restart. Check unchanged request/response forwarding and bounded memory/time, plus synthetic sentinel scans of accessible logs and artifacts. Exercise host-call failure, timeout and queue-full behavior, and prove traffic continues when capture is unavailable; Envoy filter fail-open configuration and startup/update failure behavior require separate real tests. Measure synchronous callback cost and the gateway's overhead rather than inferring nonblocking behavior from `Continue`. Existing JSON parsing allocates and runs synchronously, so a two-millisecond checkpoint is a limit mechanism, not proof of p99 latency or full preemption. Confirm whether retained Wasm memory clearing is observable and avoid claiming zeroization of all VM/host copies.

A passing synthetic slice would establish only that this fixed gateway and narrow JSON profile enforce the tested local privacy boundary. Production requires further review of host security posture, policy/secret lifecycle, enrollment and revocation, durable anti-rollback across restarts, capture source ownership, export authorization, resource isolation, request cancellation, deployment, rotation, HA and measured performance.
