# Local managed certificate lifecycle fixture

The local single-writer manager issues synthetic leaf certificates with OpenSSL, validates trust, server purpose, exact DNS SAN, current validity and key agreement, and publishes a private version directory. It atomically replaces `current`, retaining one prior version for rollback. Renewal decisions use the actual certificate expiry and a caller-provided threshold. The CA certificate and private key must be outside the published directory. The caller must serialize operations and protect the CA key and publication directory. This is a local issuer, not a production CA integration or an automated scheduler.

The optional gateway fixture uses file-based SDS. Envoy's [v1.37 SDS documentation](https://www.envoyproxy.io/docs/envoy/v1.37.0/configuration/security/secret) describes filesystem rotation, and the [configuration source documentation](https://www.envoyproxy.io/docs/envoy/v1.37.7/api-v3/config/core/v3/config_source.proto) requires the SDS source to exist at configuration load. The manager generates a bounded document naming immutable, validated version-specific leaf files. The fixture copies its bootstrap document into Linux tmpfs and atomically replaces the document there after renewal or rollback. Envoy mounts the leaf directory read-only; the CA private key is outside that mount. The fixture owns the named containers and confirms cleanup before reporting success.

Committing a manager version and publishing the document are separate steps. A failed publication leaves the manager's current version changed and does not prove Envoy changed; stop and reconcile rather than continue rotations. Successful document publication likewise does not prove Envoy loaded it: the fixture separately checks a new authenticated connection's fingerprint and application exchange. Existing connections retain their original TLS session; this does not establish preservation of client mTLS identity. The fixture is single-writer and synthetic; crash recovery, production CA, scheduler, durable publication reconciliation and high availability are not implemented.

Run `python3 -B -m unittest discover -s tests/gateway -p 'test_certificates.py'` for local lifecycle checks and `python3 scripts/test-managed-certificate-lifecycle.py` for the pinned Envoy exchange (requires the pinned image already present). The latter disables container logs and requires successful container and server cleanup before reporting success.
